1. Executive Architecture Overview

DocIntel is a centralized company document intelligence and lifecycle management platform. It ingests unstructured and structured physical documents (Invoices, Quotations, Tenders, Purchase Orders, Agreements), extracts business-critical metadata via Optical Character Recognition (OCR) and heuristics, persists relational records in MySQL, and delivers executive dashboards with real-time deadline and audit tracking.

3. Database Architecture (`database/`)

DocIntel stores data across 5 core relational tables in MySQL (Database name: docintel).

database/schema.sql DDL Blueprint

Creates the schema and 5 relational tables with cascading constraints and high-efficiency indexes on search paths:

  • users: Authentication identities, bcrypt salted passwords, and Role-Based Access Control (USER, ADMIN).
  • documents: Physical file metadata, storage location on disk, workflow status (PENDING, DONE), processing state (UPLOADED, PROCESSING, PROCESSED, FAILED), issue and due dates, soft-deletion attributes.
  • document_information: 1-to-1 extension table holding AI-extracted entities (Vendor name, GSTIN, PAN, document number, financial amount, executive summary, bullet points, and raw OCR text).
  • search_history: Logs search queries, applied filters, and result counts per user for instant recall and suggestion chips.
  • document_history: Comprehensive enterprise audit trail capturing all lifecycle events (UPLOAD, VIEW, SEARCH, UPDATE_STATUS, EDIT_META, DELETE).
database/seed.sql Seed Records

Populates the database with realistic corporate seed records, including an initial administrator account (admin@docintel.com), default employee accounts, and pre-indexed sample invoices and tenders.

4. Python OCR & AI Intelligence Engine (`python-service/`)

A standalone microservice that processes document files, converts images/PDFs into text, determines document categories, and extracts structured key-value attributes.

python-service/app.py FastAPI Entrypoint

Initializes the FastAPI application, sets up CORS origins, exposes GET /health, and serves POST /process. Receives { "document_id": int, "file_path": str }, invokes the processing pipeline, and returns the structured extraction payload.

python-service/processing/text_extractor.py Text Extractor

Performs multi-format document ingestion:

  • PDF Processing: Uses pdfplumber and PyPDF2 for digital text. If a PDF contains scanned images or yields fewer than 50 characters, it converts pages to high-resolution images for OCR fallback.
  • Image Processing: Utilizes OpenCV (cv2) for computer vision preprocessing (grayscale conversion, Gaussian bilateral filtering, adaptive Otsu thresholding), then runs pytesseract.image_to_string().
  • Tesseract Detection: Automatically scans Windows paths (C:\Program Files\Tesseract-OCR\tesseract.exe) to configure the OCR binary without requiring manual environment path setup.
python-service/processing/classifier.py Classification Engine

Evaluates extracted text using weighted keyword matching and regular expressions to classify documents into: Invoice, Quotation, Tender, Purchase Document, Agreement, or Other.

python-service/processing/information_extractor.py Entity Extractor

Extracts structured key-value entities:

  • GSTIN Regex: \b[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}\b
  • PAN Regex: \b[A-Z]{5}[0-9]{4}[A-Z]{1}\b
  • Monetary Totals: Captures currency symbols and comma-formatted decimal amounts.
  • Dates & Deadlines: Robust date parser supporting international and Indian formats (DD/MM/YYYY, YYYY-MM-DD, DD-Mon-YYYY).
  • Summary Synthesizer: Automatically generates an executive synopsis summarizing the company, document purpose, financial commitment, and deadline.

5. Node.js Express API & Business Layer (`backend/`)

backend/src/server.js API Entrypoint

Configures Express, CORS, JSON/urlencoded body parsing, static file serving (/uploads directory), router mounting, and error handling middleware on port 5000.

backend/src/config/db.js Database Pool

Creates an asynchronous connection pool using mysql2/promise with connection pooling (10 connections limit). Provides connection validation and connection lifecycle management.

backend/src/middleware/authMiddleware.js & roleMiddleware.js Security Guards

• authMiddleware: Validates Bearer JWT tokens from the HTTP Authorization header and attaches the authenticated user payload to req.user.
• roleMiddleware: Restricts administrative endpoints strictly to users with role = 'ADMIN'.

backend/src/services/documentService.js Core Business Logic

Central business service containing:

  • getStats(): Unified Dashboard Statistics. Computes real-time counts across the database: Total Documents, Pending Processing, Upcoming Deadlines (within 14 days), Overdue Documents (past due dates where status ≠ 'DONE'), and Purge Queue count.
  • getDocuments(): Dynamic parameterized SQL query builder with search queries, document type facets, date sorting, and pagination.
  • updateDocument(): In-line metadata updates, committing changes to both documents and document_information and recording audit logs.
  • deleteDocument(): Safe soft-deletion with audit logging.
backend/src/services/pythonProcessingService.js AI Service Bridge

Issues asynchronous HTTP requests from Node.js to Python (http://localhost:8000/process). Upon receiving AI extraction results, updates document_information via SQL UPSERT and marks the document as PROCESSED.

8. Critical Algorithms, Calculations & Problem-Solving Ledger

1. Unified Overdue Calculation

The Problem:

The Dashboard previously hardcoded overdue documents to 0, while the top notification banner showed 2 overdue documents and Document Dates showed 2 overdue documents.

The Solution:

Implemented a single SQL query in documentService.js checking: (COALESCE(d.due_date, di.due_date) < CURDATE() OR d.status = 'FAILED') AND d.status != 'DONE'. Documents already marked DONE are never flagged as overdue blockers.

2. Upcoming Deadlines Window (1–2 Weeks)

Defines upcoming deadlines as active documents with due dates between today and 14 days in the future: COALESCE(d.due_date, di.due_date) BETWEEN CURDATE() AND DATE_ADD(CURDATE(), INTERVAL 14 DAY) AND d.status != 'DONE'.

3. Search Logging & Deduplication

Repeated searches within short intervals update the existing query's timestamp rather than polluting the database with identical entries, ensuring a clean history feed.

4. Activity Feed Throttling

Repeated document view events by the same user within 5 minutes are throttled at the API level, preventing spam in the audit logs while maintaining accurate access counts.
